# PR #1: feature/hook-reference-folders

Let agents search RAG Web's top-level folders (`0a11ff5`, merged on 2026-11-26). Written after the fact, on 2026-11-26, from the commit, the orchestrator's tool calls and the usage records; no process report was kept at the time.

## What happened

The planner of layer 1 could not run Grep or Glob on RAG Web's `src`, `test`, `migrations`, `scripts` and `docs`, while their subfolders worked: `isReferencePath` accepted a one-component path only when it was a listed file. The orchestrator fixed the hook directly, because no agent may edit the hooks.

## Decisions the AI took without asking

- Besides opening the top-level folders, Grep now refuses a RAG Web folder with a secret file anywhere below it, because Grep reads contents; Glob only lists names. Recorded in design section 8.

## Plan against what was done

No planner: a small hook fix the orchestrator made when the planner was blocked. The tests were written before the fix (the transcript shows the test edits before the hook edits), then the whole hook suite passed.

## Findings funnel

No audit: the auditors read only the application code (`src/`, `test/`, `migrations/`), not `.claude/hooks/`.

## Test quality

New cases in `.claude/hooks/tests/agent-scope.test.mjs` for each top-level folder, for Grep and for Glob, and for a folder with a secret file below it.
