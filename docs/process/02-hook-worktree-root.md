# PR #2: feature/hook-worktree-root

Make an agent's worktree its project root (`0e025cb`, merged on 2026-11-26). Written after the fact, on 2026-11-26, from the commit, the orchestrator's tool calls and the usage records; no process report was kept at the time.

## What happened

A dry run of the test-writer in the layer 1 worktree could not write there. Claude Code sets `CLAUDE_PROJECT_DIR` to the main checkout even for an agent working in `.claude/worktrees/<name>`, and the hook blocked that folder, so the agent could still read the main checkout but not write in its own worktree. The orchestrator fixed the hook, and a second dry run confirmed the fix.

## Decisions the AI took without asking

- An agent working in a worktree has that worktree as its project, and cannot reach the main checkout or another worktree; the settings still come from the main checkout's `.env`. Recorded in design section 8.

## Plan against what was done

No planner: a small hook fix found by the dry run. Tests first, then the whole hook suite.

## Findings funnel

No audit: the auditors do not read `.claude/hooks/`.

## Test quality

New cases in `.claude/hooks/tests/agent-scope.test.mjs` for an agent in a worktree: it writes there, and it reaches neither the main checkout nor another worktree.

## Rework

The two dry runs of the test-writer (the one that found the bug and the one that confirmed the fix) are counted here, not in layer 1.
